## Appendix A — Dormant serverless API deployment plan

This appendix is inactive until either an external party asks for API access or M5 feed size makes
direct downloads unwieldy. Provisioning before a trigger is prohibited by D-010.

### Primary path: Cloudflare Workers

1. Create an isolated `deploy/cloudflare-api` Python 3.13 Worker adapter. Do not import the current
   PyArrow/threading-backed process; consume the same versioned JSON publication contract so the
   nine response schemas and OpenAPI document remain unchanged.
2. During CI, run the normal deterministic publication target, copy only the required JSON feeds
   into the Worker assets bundle, and fail if their manifest differs from the Pages artifact.
3. Use Cloudflare's FastAPI ASGI entrypoint and a 60-request/60-second rate-limit binding keyed by
   the connecting IP. Preserve open GET CORS, conditional ETags, cache headers, read-only routing,
   and 404/503 behavior in shared contract tests.
4. Configure `api.dfri.camelon.app` as a Worker custom domain. Cloudflare creates the DNS record and
   certificate; no origin, VM, SSH access, or persistent filesystem is introduced.
5. Deploy only from a protected GitHub environment using least-privilege
   `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` secrets. Pin the official deployment action by
   commit SHA and preserve its receipt.
6. Before promotion, require OpenAPI equality, no mutation routes, a real 60/minute rejection test,
   CORS/ETag/cache checks, p95 below 300 ms, and a complete live uptime receipt. Only then set
   `DFRI_API_BASE_URL=https://api.dfri.camelon.app/`.
7. Roll back by redeploying the prior Worker version; do not alter Pages feeds or immutable rows.

Cloudflare's current official documentation confirms Python Worker FastAPI/ASGI support,
[GitHub Actions deployment](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/),
[rate-limit bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/),
and [custom-domain DNS/TLS management](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).

### Compatibility fallback: Fly.io auto-stop

Use Fly.io only if the Worker adapter cannot preserve the committed API contract within supported
Python packages. Build the current application and publication directory into an immutable image;
run one Machine with `auto_start_machines = true`, `auto_stop_machines = "stop"`, and
`min_machines_running = 0`; use no volume. Deploy from GitHub Actions with an app-scoped token,
attach `api.dfri.camelon.app`, and require the same pre-promotion and uptime gates. Automatic stop
avoids an always-on VM, while a single process preserves the existing fixed-window limiter. The
fallback follows Fly's official [auto-stop configuration](https://fly.io/docs/reference/fly-proxy-autostop-autostart/)
and [GitHub Actions deployment](https://fly.io/docs/launch/continuous-deployment-with-github-actions/).
